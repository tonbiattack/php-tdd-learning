# 09. Next Steps: TDD を続けるために

## この教材の範囲

ここまでで、純粋関数、入力の境界、例外と状態不変条件、依存性注入、ファイル I/O、HTTP の入出力契約を扱いました。これらは PHP の日常的なアプリケーションコードで再利用できる基礎ですが、すべての原典テーマを実装したわけではありません。対象範囲は [coverage-matrix.md](../coverage-matrix.md) を確認してください。

## 実務での一周

新しい機能では、利用者が観察できる結果を一文で書き、その一文をテスト名にします。テストを失敗させた後にのみ実装を追加し、成功したら重複・命名・責務を整えます。変更後は必ず全テストを実行します。

```bash
composer test
composer lint
```

ユニットテストでは、時間、乱数、ネットワーク、ファイルシステムなどの外部境界を注入可能な小さな抽象に分けます。一方、境界が正しく接続されていることを確認する少数の統合テストも残します。第 07 章の一時ファイルを使うテストは、後者の最小例です。

## 発展課題

| 課題 | 先に書くべきテスト | 学べること |
|---|---|---|
| CLI ToDo アプリ | `$argv` のサブコマンドと終了コード | 入力パース、標準出力、プロセス境界 |
| HTTP アダプター | 実際のリクエストから 200/400 を返すこと | ルーティング、変換層、統合テスト |
| 非同期クライアント | タイムアウト時に副作用を残さないこと | キャンセル、リトライ、外部 I/O |
| 静的解析 | 誤った配列形状を検出すること | PHPStan/Psalm、PHPDoc テンプレート |
| 永続化の強化 | 保存中に失敗しても旧ファイルを保つこと | 原子的置換、復旧、例外設計 |

次の機能を大きく作り始める前に、テストを一つだけ追加してください。**小さく失敗し、小さく成功し、小さく整える**というリズムを保つことが、TDD を継続可能にします。
